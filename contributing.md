Thank you for taking the time to help improve Block Fall. The most useful contributions are clear bug reports, reproducible test results, accessibility observations, and thoughtful feature suggestions.

## Ways to contribute

### Report a bug

Open an issue in the [Titris GitHub repository](https://github.com/darshseraphic/Titris) and include:

- A short, descriptive title.
- The Block Fall version shown in `manifest.json`.
- Your Chrome version and operating system.
- Clear steps to reproduce the problem.
- What you expected to happen and what actually happened.
- A screenshot or console error, when it helps explain the issue. Remove personal or sensitive information first.

For extension loading or startup problems, also check `chrome://extensions` for an error message. You can inspect the extension service worker from the Block Fall card on that page.

### Suggest an improvement

Open an issue describing the problem the suggestion would solve, the intended behavior, and any accessibility or usability considerations. Keep suggestions focused so they can be evaluated clearly.

### Test an official release

Install and test an official, unmodified copy for personal, non-commercial evaluation. Report reproducible results, including the Chrome version and the controls or game state involved. Do not distribute modified builds or copies.

## Review process

The project maintainer reviews bug reports and suggestions and decides whether to investigate or implement them. Submission of an issue or suggestion does not guarantee acceptance, implementation, or a response by a particular date.

## Community expectations

Be respectful and constructive. Do not post passwords, personal data, private browsing information, or security-sensitive details in public issues. Security vulnerabilities should be reported privately using the process in [`security.md`](security.md).
